# 会话默认信任与可读标题

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/session/model/toolApproval.js

## 问题

聊天、审批选择器和定时任务分别默认请求审批，与产品要求的完全信任不一致。模型目录别名绕过 mini 展示规则。会话标题直接截取首条消息，引用会话时会把协议标记和线程 ID 写入临时标题，模型失败后仍然保留。

## 决策

### 实现方案

前端审批模块拥有统一的完全信任默认值。聊天优先使用当前会话或用户保存的显式选择，新会话不从智能体隐含配置继承审批默认值；选择器与定时任务复用相同常量。后端省略审批字段的协议行为保持原契约。

模型选择器对目录别名和模型名统一应用 mini 的最后一段截取，悬停保留完整名称。标题 service 在写临时标题和调用命名模型之前，将会话引用逐层替换为可读标签，处理旧标题中残留的嵌套引用，缺少标签时使用“引用会话”；原始消息和实际执行输入不变。标题写回继续遵守一次命名及手动改名优先。

## 替代方案

- 修改后端全局审批默认值：会扩大到 API 调用者和现有配置，不符合前端默认值的范围。
- 仅缩短 CSS 文本或仅清理模型生成结果：不能修复 mini 语义或命名失败时的持久标题。
- 改写已保存会话和用户偏好：会覆盖明确选择，不采用。

## 后果

完全信任允许敏感工具自动执行；前端保留请求审批选项及用户已保存的选择。标题使用引用中的显示标签，不读取其他会话内容，不批量改写已有标题。账户文案、角色色、技能卡片边框和编辑弹窗布局遵守既有展示规范，暗色卡片的规则仅作用于技能卡片。
