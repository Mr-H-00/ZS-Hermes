# 完整 CodeQL 基线与按数据流处置结果

状态：implemented
类型：bug-fix
Owner：.github/workflows/codeql.yml

## 问题

PR 差异分析没有新增结果，不代表当前源码没有完整扫描结果。恢复持续扫描后，默认分支首次完整分析发现 runner 健康错误响应和模型重放正则的缺陷，以及凭据类型、临时文件与既有授权校验未被静态分析正确识别的结果。

## 决策

### 实现方案

保留三语言 CodeQL 与全部安全规则。恢复或调整扫描装配时，使用已有 workflow_dispatch 在交付分支执行完整分析，并回读该提交的所有结果，不能用 PR 新增数替代完整基线。

runner 健康接口在进程日志记录完整异常，对 HTTP 仅返回稳定的不可用错误。重放服务用线性标签提取替换附件上下文的重复正则搜索，保持现有 oracle 的嵌套、空与未闭合语义。

静态分析结果由实际数据源和副作用边界判定：高熵随机 Key 索引不作为密码派生函数；幂等请求 ID 不作为认证凭据；Cookie 值受固定字符和长度约束；宿主文件操作由 owning filesystem、包解析或服务临时文件拥有。逐条保留实际源点、sink、现有负向证据和独立审查依据，再使用 GitHub 可撤销的误报或测试用途状态处置；不以新增屏蔽规则、路径排除或改写正确代码替代证据。

## 替代方案

只看 PR 新增结果会漏掉首次基线；将快速索引改成密码派生函数会破坏随机 Key 查询及持久指纹协议；为了迎合扫描器更改临时文件扩展名、存储键或安全路径抽象会引入不必要的兼容成本。全量忽略或关闭规则不能区分真实缺陷。

## 后果

误报结论依赖当前源点和执行边界，变更这些边界必须重新审查。权限 E2E 的 MCP fixture 为 worker 容器监听临时端口，工具只写测试目录并随 fixture 清理；其隔离测试拓扑不外推到生产服务。运行时错误诊断保留在受控进程日志中。
