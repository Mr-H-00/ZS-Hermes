# 外部编码准则收窄合入开发约定

状态：implemented
类型：process
Owner：AGENTS.md

## 问题

一组通用 Python 编码准则（基础规范、认知复杂度优先、自顶向下组织、表达式直观、排版注释、克制抽象、重构保持行为）需要并入仓库约定。原样采纳会与更严格的既有规则冲突：PEP 8 行宽对 Ruff 140、无条件自顶向下重排对最小修改范围、总结性注释对"只解释非显然信息"、顺手去重对"发现坏味道只说明不擅自处理"。

## 决策

除 PEP 8 行宽继续由 Ruff 配置拥有外，逐条对照既有 Owner 后只合入真实缺口，并按既有更严格规则收窄：

- 表达式：推导式与三元表达式只承载简单映射、过滤和转换；嵌套遍历、多步转换或大段对象构造用显式循环和条件语句，不机械展开清晰的惯用表达式。
- 阅读顺序：向下规则补充公开、高层方法按业务流程排列且相关定义相邻，仍限于本次新增或实质修改的代码，不重排整个文件。
- 注释：在"解释非显然约束、时序、Owner 和安全用法"之上，较长处理段可在段首用一句话概括职责与阶段；逐行翻译代码仍被禁止。
- 修改纪律：重构保持业务行为、API 契约、异常处理与异步并发语义不变，以相关测试验证；重复逻辑只在本次修改范围内收敛。
- 未合入项：主流程线性、拆函数尺度、信任边界校验、shared 归属、最小修改范围等已有更严格 Owner，不重复添加。

### 实现方案

通用注释纪律与修改范围由根 `AGENTS.md` 拥有；后端 Python 的表达式、阅读顺序、去重与重构规则由 `backend/AGENTS.md` 拥有；后端排版细节（含段首概括注释）由[贡献指南后端节](../../contributing.md)拥有。执行方式为独立 Reviewer 对照 AGENTS 条款核查，`scripts/ci/verify_engineering_contracts.py` 校验结构、链接与字符预算，不新增机械检查。

## 替代方案

原样采纳外部准则：与 Ruff 行宽、最小修改范围和不擅自清理规则直接冲突，拒绝。不合并、仅在评审时口头掌握：表达式与段首概括注释无 Owner，评审尺度漂移，拒绝。

## 后果

较长处理段出现段首一句话概括属于合规，仅复述代码或逐行翻译仍被拦截；自顶向下调整与去重限于本次修改范围，不产生整文件重排 diff；行宽权威保持在 `backend/pyproject.toml`，"遵循 PEP 8"不含行宽含义。
