# Agent 中间件输入与执行边界修复

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/agents/runtime/middlewares/summary.py

## 问题

模型请求视图、当前授权与副作用收尾分别由不同边界拥有；混淆这些事实会造成丢失上下文、撤权后继续执行或取消后提前释放资源。开启 Memory 时空文件也必须允许写入第一条记忆。

## 决策

### 实现方案

摘要保持原始消息与请求视图分离，通用工具预览保留可回读的原文，多模态非文本块继续参与模型请求。自动与主动压缩共用历史归档和摘要核心；自动压缩在主模型成功后提交摘要事件并报告完成。摘要输入按已知窗口预留输出，未知窗口使用独立小预算并记录警告。主模型服务端上下文超长触发压缩；摘要请求仍超长时，实际历史输入预算逐轮缩至上一次的 80%，最多额外重试 5 次，每次重新授权。无法继续缩减时保留原超长错误。固定摘要指令、输出预留和完整归档不随重试缩减。

授权在实际执行边界复查。Skill 请求固定已注入来源，事务成功退出后才发布刷新快照；共享预加载身份包含数据库行和当前正文摘要，个人来源使用根文件身份，专属 Skill 的同一行修订保留本 Run 准备正文。共享依赖按 slug 无锁筛选后加锁复核，避免全量候选查询和不可见行的锁等待。Skill 提示与工具绑定使用统一正式路径，不提供测试专用提示开关。临时 MCP 发现失败不占用成功目录缓存，直接配置与激活依赖可在后续模型请求恢复；缺少可信知识范围明确限制能力。MCP 权限拒绝在 owning middleware 传播为执行拒绝，不被外层工具保护转成普通错误结果。

可中断执行器接收取消，不可中断写入在实际 I/O 边界等待收尾。Memory 服务用空字符串表示开启但尚无内容，使用 None 表示关闭。图片处理仅在 OpenAI 桥接工具图片，但所有 provider 都移除已请求 OCR 的图片。网络分类保留 Python 与领域权限拒绝，避免异常链中的连接错误触发重试。知识文档按完整行限制整个 MCP 响应为 64 KiB，前端按实际偏移和窗口大小维护翻页历史。

文档窗口统一装配完整行前缀，以二分检查文本与结构化 MCP 结果的共同字节预算。单行超限使用领域错误码 `document_line_too_large`，经正式 HTTP 异常处理返回可识别的 413 业务详情；前端上一页探针只在该错误码下向后收窄，网络和权限失败保留错误恢复入口。授权刷新只接受真实 Context 契约，浅拷贝保存运行内对象引用，事务成功退出后统一发布声明的资源字段与 Skill 快照。

## 替代方案

用全局 shield 保护所有工具会阻止可取消执行器接收取消；用统一的空值表示 Memory 状态会隐藏首次写入工具。对所有 provider 桥接图片会改变其原生协议。未知模型窗口直接失败会阻断现有兼容模型，因此接受有明确限制的保守尝试。无限次缩减摘要输入会放大等待和调用成本，因此重试最多 5 次。

## 后果

输入估算不是供应商计费 token，也不能证明所有未知模型窗口均适配。历史 XML 是阅读档案，原始消息与元数据由 Message/checkpoint 拥有。权限刷新仍扫描个人来源并同步投影；省略这些工作需要先证明来源遮蔽、当前闭包和实际文件访问的撤权语义，不以过期缓存换取较少查询。
