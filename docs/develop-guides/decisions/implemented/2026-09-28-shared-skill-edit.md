# 共享 Skill 在线编辑

状态：implemented
类型：feature
Owner：backend/yuxi/modules/extensions/skills/edit.py

## 问题

共享 Skill 的根说明、元数据和依赖必须同步；切换文件不能丢弃草稿，保存失败不能让当前文件与数据库索引分叉。既有文件级 HTTP 契约与当前整包编辑器需要共享真实内容 Owner。

## 决策

### 实现方案

edit.py 拥有读取、导出及现有单文件、依赖、节点 HTTP 写入的适配；路由转换请求与响应。管理者、来源、no-follow 路径和文件类型在所属边界校验。文件级请求提交预期文件修订，由 content.py 在资源锁内核对，转换成完整包的一项变更。根说明与依赖表单都更新同一 frontmatter 和数据库索引。

完整不可变目录、整包修订、数据库引用提交与清理由[完整内容提交决定](./2026-10-05-skill-content-commit.md)拥有；本记录不再定义原地替换、暂存删除或异常恢复旧文件。权限变更仍由共享索引 service 先撤回投影、提交权限、重建投影。个人来源由个人工作区拥有。

详情页维护一份完整内容草稿，跨文件和页签保留；文件与依赖表单编辑同一根说明，显式保存全部修改。冲突保留草稿，放弃或加载最新内容需要确认。读取与恢复忙碌期间阻止编辑和离开，后续响应不能覆盖新输入。专属绑定与历史入口见[专属 Skill 决定](./2026-10-03-agent-bound-skill.md)。

根文件解析只在标准 YAML 解析失败时，将未引用的多行 description 按折叠文本重试；其他错误继续拒绝。

## 替代方案

- 保留文件原地发布与提交失败补偿：无法统一完整草稿和不可变历史，已由 content 用例取代。
- 前端不再调用后立即删除原 HTTP 契约：前端迁移不代表既有公开协议没有外部调用；本次保留薄适配，避免另建持久化路径。

## 后果

旧文件级调用者沿用对应文件修订；当前前端使用整包修订，跨文件并发编辑也可能发生冲突。运行根保留准备时内容，辅助文件沿用实时投影。YAML 序列化可能重排 frontmatter 或丢失注释，正文保持原样。受管理当前内容不再承担原地文件替换与数据库提交之间的补偿窗口；物理内容损坏不承诺自动恢复。

## 验证

当前实际证据由完整内容提交决定和 PR 汇总：后端 unit、真实 HTTP/PostgreSQL 共享编辑与原子内容集成、worker E2E、前端组件与真实页面回读均通过；包含单文件既有契约、整包冲突、索引/文件一致性和失败保留。

工程契约、脚本单测、Ruff、前端 lint/unit/build、文档相对链接和构建通过。商业模型、第三方服务和生产恢复未执行，不将历史版本验证当作当前结果。
