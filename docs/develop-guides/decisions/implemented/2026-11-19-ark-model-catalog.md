# 火山方舟模型目录与调用协议

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/models/providers/ark.py

## 问题

方舟的一个目录同时列出对话、向量、图像和其他任务。把整个目录归入对话会影响模型选择，并丢失上游提供的上下文和模态信息。

## 决策

### 实现方案

模型供应商服务按官方目录地址识别方舟。单个模型的接口、任务、领域和输出模态决定分类。缺少声明时可依据已知型号补充分类，Seed Audio 系列按模型 ID 归入语音。候选列表使用方舟返回的条目，过滤同名的旧版 `doubao-seedream-4-0-250828`，保留 `doubao-seedream-4-0-20260415`。目录读取、添加模型和采用远端规格分别对应发现、首次启用和显式更新。

上下文取方舟声明的 token 限额。目录未声明维度时，管理员可主动发起连接测试，从一次成功的向量响应读出维度并确认保存。文本向量优先使用标准接口，仅支持多模态接口的模型逐条编码，维持一篇文档对应一个向量。管理员配置的执行地址优先。重排候选须有类型证据或独立分类端点。

## 替代方案

按模型名维护类型与维度需要追踪每次上新。让管理员逐条手填会丢失目录已经提供的信息。

## 后果

方舟新增型号可以使用已有的能力声明自动分类。没有可用证据的条目保留为未识别。目录刷新不会覆写历史配置。上下文和实测维度可在模型管理页保存；已建知识库仍使用创建索引时确定的维度。

## 验证

目录回放覆盖混合目录、重复端点、上下文缺失及其他供应商。本地 HTTP 服务验证多模态向量的同步、异步批次与响应维度。管理面板用例覆盖候选类型、显式采用远端规格和保存动作。真实方舟目录用于校对能力分布。推理协议验证使用受控响应。
