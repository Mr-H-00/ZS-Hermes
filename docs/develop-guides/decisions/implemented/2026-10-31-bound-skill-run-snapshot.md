# 专属 Skill 编辑保留当前 Run 的准备正文

状态：implemented
类型：bug-fix
Owner：backend/yuxi/modules/extensions/skills/runtime.py

## 问题

专属 Skill 编辑通过不可变目录提交更新同一数据库行的内容摘要。运行时把摘要变化当作绑定身份变化，后续模型请求会读取编辑后的正文，与当前 Run 已准备的内容和清单不一致。

## 决策

### 实现方案

专属 Skill 仍属于同一数据库行且当前调用者仍获授权时，保留当前 Run 已准备的预加载正文及其来源元数据。同名绑定被新行替换时重新读取来源；新 Run 准备时读取当前正文。共享、个人 Skill 的来源识别与执行边界的权限复核保持现有契约。

该规则落实[中间件输入与执行边界决定](./2026-10-30-agent-middleware-repair.md)的同一绑定快照约束，不固定可见性、依赖权限或文件投影。

## 替代方案

按完整内容摘要复核专属根正文会让在线编辑改变当前 Run 的提示。仅按 slug 复用正文会把已删除绑定的旧内容带入同名新来源，均不采用。

## 后果

编辑后的正文从下一 Run 生效；当前 Run 的工具与资源授权仍使用执行边界的当前权限。文件投影反映当前持久内容，不能作为当前 Run 预加载正文的替代来源。

## 验证

真实 PostgreSQL 与正式内容提交用例验证编辑确实改变目录引用和摘要，当前绑定保留准备正文，同名新行与新 Run 使用当前正文。现有撤权与来源替换测试继续验证旧提示不能绕过当前授权。API/worker E2E 在首次模型请求阻塞时编辑专属根文件，由独立模型协议检查后续请求仍携带准备标记，并回读 Run 清单和当前文件。
