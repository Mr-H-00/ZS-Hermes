# 角色、共享资源与私有 Agent 权限收敛

状态：implemented

类型：feature
Owner：backend/yuxi/modules/identity/permissions/resource_permission.py

## 问题

共享资源管理权限与角色上限不一致，主 Agent 缺少独立私有状态，账号管理和长生命周期执行需要使用当前身份与授权闭合隔离。

## 决策

角色限制共享资源建设与管理，资源授权限制可使用与管理的对象。主 Agent 默认私有，所有者可以管理；有管理权限的管理员可将私有主 Agent 单向共享，系统管理员可以治理共享他人的私有定义。创建及更新入口由[统一创建与配置决定](./2026-10-05-agent-create-context.md)拥有；私有运行与所有权转移仍遵循各自边界。共享范围采用同类型子集规则，指定管理者必须为有效管理员。账号角色只升不降，至少保留一个有效系统管理员。APP 终端用户只能使用共享 Agent；执行边界重新读取调用者授权。

按新版本直接修改契约，不保留旧权限行为、不迁移历史授权数据。个人 Skill、会话和文件隔离沿用原有 Owner，不增加策略引擎、自定义角色或审批机制。

### 实现方案

Identity permission 解析角色上限、同类型范围与私有可见性，资源写入服务校验指定管理者；User repository 与 PostgreSQL 触发器共同保证锁定后的成员授权、只升不降与系统管理员存续。Agent repository 保存明确的 visibility 和内置标记，发布在定义行锁内完成校验与状态提交，专用系统接口转移共享资源所有权。

HTTP 依赖限定系统维护入口，directory 与 worker 使用实际调用者的可运行查询。运行授权中间件在每次模型请求（包括重试）、模型返回后和工具边界刷新身份与资源；Agent 和摘要模型关闭 SDK 内部重试，Agent 重试由外层中间件拥有；独立摘要在请求前复查权限，没有 Run 的主动压缩使用归属已验证的 Thread 读取当前 Agent，子 Agent 启动服务在子执行持久化前重新授权；账号或 Agent 失权形成失败结果，依赖失权通过通用事件和工具结果提示。前端使用返回的 capability flags 选择创建与运行入口，并保留字段角色限制；发布复选框变化即可显式保存，新 SubAgent 可以限定共享范围。

Agent 更新、删除、发布及共享资源转移在资源行锁之后重新读取有效人类操作者，并持有身份共享锁直到提交；配置补丁在同一锁内按当前角色和部门重新解析可访问资源；等待期间删除或移出授权部门必须拒绝且不改变定义。成员管理使用共同事务锁，在锁定目标后重新读取操作者，等待期间调部门或删除后拒绝写入。Skill 批量安装每项事务重新校验指定管理者，避免沿用前项提交后释放锁的结果。移除可取得他人正常 JWT 的模拟登录接口及前端入口；性能测试登录自己创建的账号。HTTP/数据库和真实 worker 撤权回归接入 system-tests workflow，失败阻止交付。既有共享 Agent 测试夹具显式声明 shared，不沿用私有默认；普通用户字段写入用私有所有者验证高级字段拒绝与基本编辑，委派共享管理用真实晋升后的管理员验证资源补丁，并接入 CI。

## 替代方案

保留根据授权列表推断私有状态会混淆治理和正常运行；继续允许普通用户管理共享定义会突破角色上限。二者均不采用。

## 后果

持久状态变更使用新的独立数据库环境，业务 Schema 版本为 4，不匹配的库在启动校验和初始化入口显式拒绝；旧授权与旧数据不受兼容承诺。执行失败沿用既有暂停 FIFO 队列的契约，排队输入保留，显式继续后重新授权。等待取消是按持久 Run 与完整 Thread 归属执行的服务端 checkpoint 维护，不取得用户资源使用权，也不运行模型或工具。

## 验证

验证在独立 Docker Compose 项目和全新 PostgreSQL 数据库执行。HTTP 测试回读定义、账号和授权；并发测试使用真实连接锁验证成员变更、系统管理员存续及恢复与删除的锁序。E2E 通过真实 HTTP 模型协议、worker、PostgreSQL checkpoint、MCP 和文件副作用证明当前权限，模型回复由本地确定性协议服务提供。

- `python3 scripts/verify_engineering_contracts.py` 与 `python3 -m unittest scripts.test_verify_engineering_contracts`：通过，64 项脚本测试通过。
- `docker compose exec --user 0:0 -T api uv run --group test pytest test/unit -m "not slow"`：2518 项通过、55 项跳过。真实 HTTP/PostgreSQL 集成集合 44 项通过，包含 21 项身份/授权、11 项模块失败边界、1 项 APP 身份、6 项隔离 Schema 和 5 项知识库统计；另有 5 项配置字段/资源授权集成通过；`test/e2e/test_permission_revocation_e2e.py`：12 项通过，包括真实 HTTP 503 重试、上下文溢出的独立摘要和无 Run 主动摘要撤权。
- 负向复现：模型请求中途撤权，旧实现在真实 HTTP 上继续发送重试或摘要请求；成员或资源行锁等待期间撤销操作者权限，旧实现仍返回成功并写入（资源写入另有 7 项真实 HTTP/数据库负向复现）；Skill 首项提交后删除指定管理者，旧实现仍将第二项写入数据库。修复后断言请求协议、持久行和文件结果。
- 前端 lint、unit、类型检查和构建通过，445 项 unit 通过。Playwright 以普通用户完成真实私有创建、编辑保存和删除，并通过 HTTP 回读结果；管理员仅勾选发布后保存并回读 shared；新 SubAgent 限定为所有者范围；系统管理员治理他人私有定义时无运行或发布入口。浅色、真实主题初始化后的深色和 390px 页面截图保存在本地验证产物中，390px 管理页面仍有既存横向溢出，未声明移动布局通过。
- 文档构建、改动文档的相对链接检查、Python Ruff check 和 `git diff --check`：通过。完整 CI 的最终提交检查由 PR 记录。

真实外部模型供应商未纳入本次权限验证；本地协议服务不替代供应商兼容性测试。当前授权在正常执行边界生效，已经提交到外部服务的动作和已经进入上下文的信息无法撤回。
