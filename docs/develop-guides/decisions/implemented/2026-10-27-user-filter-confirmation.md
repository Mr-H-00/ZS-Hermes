# 用户管理表头多选确认

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/settings/ui/UserManagementComponent.vue

## 问题

角色和部门筛选支持多选，但逐项立即生效会反复刷新列表，菜单内点击关闭还会打断选择。

## 决策

### 实现方案

用户管理组件在打开筛选菜单时复制已应用的值作为草稿。勾选和清空只修改草稿；确认将草稿应用到用户查询并关闭菜单，取消或点击外部关闭时放弃草稿。筛选结果为空时保留表头，使用户仍能调整筛选。部门搜索只隐藏不匹配项，保留全部复选框注册，避免 Ant Design 在勾选新结果时丢弃此前隐藏的已选值。

## 替代方案

逐项立即查询无需草稿，但多选时会产生中间结果和重复查询，也无法取消未完成的选择。

## 后果

用户需要确认一次才能更新结果；菜单关闭后重新打开会恢复已应用的值。角色和部门筛选共用相同的提交语义。

## 验证

前端单元测试 868 项通过，其中筛选测试检查确认、取消和清空的查询状态。真实 Chromium 执行 `frontend/test/browser/userFilters.js`，以合成响应验证多选期间不请求、确认后提交、取消与外部关闭放弃草稿、空结果保留入口、长部门名滚动，以及浅深主题和 768px 布局。跨搜索选择部门 3 和部门 4 后回读复选状态及最终请求参数，证明隐藏选择仍保留。
