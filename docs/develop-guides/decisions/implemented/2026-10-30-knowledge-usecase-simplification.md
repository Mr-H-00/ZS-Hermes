# 知识库元数据用例与执行器边界收敛

状态：implemented
类型：simplification
Owner：backend/yuxi/modules/knowledge/manager.py

## 问题

文件目录与元数据操作经过类型执行器装配，要求无关的解析配置和 Milvus 连接有效。共享文件流程位于执行器基类，HTTP 路由拥有批量删除、原件下载、工作区导入及描述生成流程，调用边界不能准确表达副作用归属。检索接口保留没有消费者的参数和失败的导出实现。

## 决策

### 实现方案

Manager 保留当前调用入口与类型分派。元数据及目录用例直接调用知识域 service/repository；类型配置与查询默认值由类型类提供，不构造检索客户端。本地文件读取、窗口、来源范围和原件下载由 `services/documents.py` 拥有；外部正文阅读继续由连接器核验远端归属和权限。解析、索引、检索及派生产物清理由执行器承担。

`services/administration.py` 组织批量删除、工作区导入和描述生成；路由处理权限、请求、状态码及响应流。下载仍流式读取并归还连接；原件非法输入、批量全失败与单项删除缺失保留 HTTP 400。文件读取目标不在库内返回 404，无法取得文件元数据或顶层用例失败返回 500。正文与分块的部分不可用继续由既有 `line_location` 结构表达，允许展示仍可读取的内容；不把顶层异常包装为 HTTP 200。

删除无运行消费者的检索参数、私有写回、运维诊断、旧单文件登记及独立参数更新入口。正式导入使用持久回执，处理参数在文件领取事务中合并，不能绕开领取保存。公开导出路径保留明确的 501 拒绝，不新增导出实现。持久字段、历史状态及外部连接配置继续保留。

## 替代方案

- 保留执行器转发：维持目录和阅读对外部连接的无关依赖，不采用。
- 沿已有 service/repository 收窄职责：保持当前消费者及数据契约，采用。
- 另建通用能力或执行框架：扩大配置与维护表面，不采用。
- 删除公开接口或存量字段：需要外部消费者与数据审计，不作为等价清理执行。

## 后果

元数据和本地正文读取不依赖检索执行器构造，默认部署启动时仍验证已使用的知识后端，不削弱 readiness。存储异常与业务拒绝保持可观察，HTTP 调用方须按失败状态处理。测试替身跟随真实服务和外部边界，不保留无用转发层来适配旧 mock。

暂存历史对象、旧评估记录与外部 OCR/飞书账号的验证边界由并行的处理所有权、解析评估和阅读状态决策分别说明；此决定不自动改写存量数据。

- `test/integration/services/test_knowledge_metadata_boundary.py`：7 项真实 PostgreSQL/HTTP 通过。正文只替换对象字节读取；数据库、路由、Manager 与 service 使用真实实现。测试接入服务 CI。
- `test/integration/services/test_chunk_config_boundary.py`：16 项真实 PostgreSQL 领取事务通过；`test_knowledge_document_resets.py`：55 项通过。
- 上传及目录导入真实 HTTP 集合共 23 项通过；真实 worker 解析产物发布、失权回收与删除链路 E2E 通过，从 PostgreSQL 和 MinIO 回读结果。

完整门禁在独立 Compose 槽位执行：后端 `uv run --no-sync --group test pytest test/unit -m "not slow"` 为 3407 通过、125 跳过及 7 个子测试通过；前端完整 unit 为 976 通过。Ruff 三项检查、前端 lint/build、文档 build、相对链接、工程契约检查及其 56 项 unittest 通过。跳过项不构成运行时链路证据，外部云模型与真实飞书账号未验证。

旧能力不存在：执行器中的纯目录及共享文件读取路径、无消费者的 `agent_call`、查询配置的知识库 ID 参数、独立参数写回、旧单文件登记、私有元数据写回和诊断入口均已删除；公开导出没有虚假的执行实现。

重新引入条件：出现需要独立生命周期或不同存储行为的真实消费者，且契约和负向测试证明现有领域服务无法表达；不得恢复绕过领取事务的参数写入。
