# 深色模式表面分层

状态：implemented
类型：bug-fix
Owner：frontend/src/assets/css/base.dark.css

## 问题

深色模式下页面底、卡片、输入框共用 `--gray-0`，只能靠细边框区分区域。若干组件引用未定义的颜色变量，退回固定浅色值或继承普通文字色；局部样式中的根节点选择器也会受 Vue 作用域改写影响，导致深色覆盖失效。

## 决策

### 实现方案

`base.dark.css` 以 `--gray-0 #1d2024` 到 `--gray-200 #4a5056` 提供表面与描边色阶，独立页面底 `--bg-page` 为 `#141619`，整体采用深灰基底。`body`、页面壳层、概览页的深色背景和主聊天底部遮挡渐变使用页面色，卡片使用基础表面色，聊天输入使用下述交互阶梯。协作嵌入面板保留所属表面色。具体灰度由色板维护，验收检查层级与可读性，不锁定某组色值。

浮层颜色由 `--color-bg-elevated` 拥有，主题 Store 读取实际色值装配 Ant Design；普通与禁用控件分别保留框架 token，不用高优先级全局背景覆盖状态。侧栏及悬停使用主题别名，浅色沿用原配色；会话列表的遮罩背景由导航容器提供，以适配主侧栏、浮动及固定面板的不同表面。设置容器的分层仅在深色覆盖。

相关失效变量和界面固定色直接改为已有主题变量，浮层阴影复用共享色板。Markdown 代码复制与 SVG 操作按钮使用中性表面色，避免透明黑白 token 在深色反转。PDF 状态提示与工具占位直接使用语义色和中性色，无需单独的深色覆盖；文档白纸复用不随主题反转的白色变量。上传取消按钮使用品牌色及其配套前景色，已定义变量不再保留固定色 fallback。

暗色以背景阶梯替代装饰描边和阴影。色板补充 `gray-20/30/40`，共享卡片边框语义色在暗色下透明，次级表格分隔线同步隐藏；嵌套的紧凑指标使用 `gray-10` 区分父卡片。浮层使用更亮的 `gray-30`，通用浮层阴影关闭，仍需阴影的旧组件只保留低透明黑色，不产生白色光晕。聊天输入框去掉边框和阴影，正常、悬停、聚焦分别使用 `gray-30/40/50`；发送与停止按钮使用白底深色图标，保留禁用不透明度和键盘焦点轮廓。空输入提示使用 `gray-600`，保持普通与聚焦背景上的可读性。拖拽和错误反馈不按装饰描边移除。浅色色板原值和控件样式保持不变。

## 替代方案

直接给裸露的 `rgba(0,0,0,...)` 阴影和固定 hex 逐个加 `.dark` 覆盖块：改动面更大，且新增的控件仍会重复出现同类问题。另一种是不改变量、只在页面容器加渐变：无法修复弹窗与输入框的同色问题。

## 后果

深色下页面、表面与浮层有独立色阶；浅色页面、侧栏和设置容器沿用原配色。失效变量与状态色修复适用于两套主题，不能据此声称所有浅色细节完全不变。`gray-0` 表达表面，页面底继续使用 `bg-page`，避免重新混用。

## 验证

前端单元测试 868 项通过。真实 Chromium 的 `frontend/test/browser/apiIntegrationSurfaces.js` 在 1280/1024/768px、浅色和深色下读取 DOM 样式，验证无整页横向溢出、深色表头、Markdown 复制按钮、PDF 错误和工具占位样式。普通与禁用输入框、选择框的背景分别读取并比较；截图等待有限动画结束。

`frontend/test/browser/composerSurfaces.js` 使用真实聊天输入与卡片组件，在浅深主题和三个验收宽度下回读样式，验证暗色输入无边框和阴影、卡片边框透明、白色发送按钮、悬停与聚焦背景变化，以及浅色原配色。通过禁用时不发送、可用时发送与停止的事件结果验证交互未改变；同时核对键盘焦点、空态提示对比度、添加菜单和弹窗；恢复旧 `gray-300` 占位文字时对比检查失败。截图只包含合成数据。

浏览器使用合成数据和真实组件，不表示逐页人工验收或外部服务已验证。全站灰阶会影响其他表面，未覆盖的具体页面状态仍需按实际使用复核。
